# Data provenance and ingestion

Every number the assistant serves traces to a named table in a downloaded official publication whose bytes are pinned by hash. Nothing is scraped at request time and no value is generated by a model.

Collection version: `2026-10-27.1` (`VERSION` in [lib/evidence.ts](../lib/evidence.ts)).

Canonical URLs and PDF links are stored with each source record. Both files were fetched from `statistics.gov.rw` and re-hashed after the collection was written:

```sh
cd data/originals && sha256sum eicv7-main.pdf lfs-2025.pdf
```

The expected digests and byte counts are recorded in [data/originals/manifest.json](../data/originals/manifest.json). A digest mismatch means NISR republished the document and every affected observation must be re-checked before the collection version is bumped.

### What is and is not in the repository

`data/originals/` is partially ignored by git. Committed: `manifest.json` and the three verified page extracts (`*-verified-*.txt`). Ignored: the source PDFs, the rendered verification captures, and the bulk page dumps. Large binaries do not belong in a review repository, and the extracts that carry the cited tables do. To reproduce verification locally, download the two PDFs from the URLs above and re-run the digest check.

Committed verification extracts:

- `eicv7-main-verified-81.txt` — Table 9.1 (headcount poverty) and Table 9.2 (extreme poverty), with the confidence-interval columns and the CV footnote
- `eicv7-main-verified-84.txt` — Table 9.3, the modelled comparable 2016/17 baseline
- `lfs-2025-verified-12.txt` — the 2025 headline labour-force summary used to corroborate the trend series

## Observation records

Observations and provenance are stored separately. Each row carries enough context to be checked without reading the code ([lib/domain.ts](../lib/domain.ts)):

```
id · indicator · value · year · period · geography · group · sourceId
· pdfPage · locator · method · estimate (survey | modelled) · ci? · caution?
```

`period` is the reference period as published (`2023/24`), `year` is the sortable key, `group` distinguishes `All`, `Female`, `Male`, and `locator` names the table and the printed page.

Current contents: 64 observations across 7 indicators — poverty, extreme poverty, unemployment, youth unemployment, labour force participation, employment-to-population ratio, labour underutilization.

## Verification rules applied when building the collection

1. **Values are transcribed, never derived.** Each figure was read from the cited table cell. The 2025 unemployment rate, for example, is the value in the trend table on page 13, cross-checked against the 12.4% headline in the summary infographic on page 12.
2. **Original values survive translation unchanged.** The number, unit, denominator and period are language-independent; only labels and prose are translated. `27.4%` is `27.4%` in all three interfaces.
3. **A survey period is not a calendar year.** `2023/24` is stored as `period`, and `2024` as `year` for filtering. The assistant answers "poverty in 2023/24" and refuses "poverty in 2026".
4. **Methodology breaks are labelled, not smoothed over.** The 2017 poverty figure is stored as `estimate: "modelled"` with the note that it is EICV7's comparable restatement, not the originally published EICV5 rate. The EICV5 published rate is deliberately absent so it can never be compared as if equivalent.
5. **High-variance estimates are withheld.** Table 9.2 flags City of Kigali (1.1%) and Northern Province (3.2%) extreme poverty with a coefficient of variation above 15%. Those two rows are excluded, so the assistant declines them rather than presenting a fragile figure as fact.
6. **Missing is not zero.** Absent observations return "unavailable". No arithmetic fills gaps, and district values are never inferred from provincial ones.
7. **Annual and quarterly series are not mixed.** The collection holds annual LFS estimates only; any quarter or month request is refused.

## Adding a publication — runbook

1. **Confirm the canonical document.** Prefer the production publication page over alpha/beta copies. Record the landing page and the direct PDF URL.
2. **Download and pin.** Save into `data/originals/`, add an entry to `manifest.json` with URL, bytes and SHA-256, and re-hash to confirm.
3. **Extract only the tables you will cite.** Keep the text extract for every table you plan to publish, and commit the verified ones as `*-verified-<pdfPage>.txt`.
4. **Add a `Source` record** in [lib/evidence.ts](../lib/evidence.ts) with a `methodology` note in all three languages, describing denominators, working-age definitions and any comparability warning.
5. **Add `Indicator` records** with the definition in all three languages and the search terms users will actually type, including Kinyarwanda elided forms (`bukene` after `mu`, `bushomeri` after `ku`).
6. **Push `Observation` rows** with the exact `pdfPage`, `locator`, `period`, `group`, `method` and `estimate` type. Add `ci` where the source publishes bounds. Never add a value you have not read in the document.
7. **Bump `VERSION`** to `<date>.<n>`. The version is shown in the footer, returned by `/api/health` and recorded in evaluation output.
8. **Lock it in.** Add unit tests in [tests/answer.test.ts](../tests/answer.test.ts) for the new intents and refusals, add the equivalents to [eval/cases.json](../eval/cases.json) in all three languages, then run:

```sh
npm test && npm run eval
```

`npm run eval` exits non-zero on any failed check and rewrites `eval/results.json` and `eval/results.md`. Commit the regenerated results with the source change so the published numbers always describe the shipped collection.

## Removing or correcting a value

Delete or edit the observation row, bump `VERSION`, and re-run the evaluation. Because answers, citations and the CSV export are generated from the same records, no stale copy survives a rebuild. If a source is withdrawn upstream, remove its `Source` record — every observation referencing it throws at build time through `sourceFor()`, which is the intended failure mode rather than a silent fallback.
